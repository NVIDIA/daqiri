# Running DAQIRI perftest

Build in the project container with `DAQIRI_BUILD_EXAMPLES=ON`. Build the `daqiri_perftest_worker` and `daqiri_config_validate` targets and use the launcher at `<build>/daqiri_perftest`. Python 3 and PyYAML are required. A socket-only build uses `-DDAQIRI_ENGINE=""`. For hardware runs select the required `ibverbs` and/or `dpdk` engines.

1. Confirm the process CPU affinity, netdev-to-BDF mapping, and actual cable or peer. For local raw cabled loopback use separate `--client-interface` and `--server-interface` arguments. For single-port raw ibverbs use `--topology hw-loopback --interface NETDEV`. For TCP and UDP smoke tests use two IPv4 loopback endpoints with distinct port ranges.
2. Run the intended command with `--dry-run`. Inspect the native validation result, queue-to-region mapping, poll modes, interface identities, and address and port ranges. Record commands for both peers in paired runs. Use the server’s control address and start its process first. Use existing namespaces for a same-host wire test when local routes would keep IP traffic in the kernel.
3. Let the launcher run `tune_system.py` checks before traffic. Report warnings and failed checks. Keep firmware queries read-only. Confirm active `REAL_TIME_CLOCK_ENABLE` and PTP clock alignment before using hardware latency results. Perftest uses `/sys/devices/system/cpu/isolated` and the process affinity mask for automatic placement. Inspect resolved cores and isolation warnings, including CPU overlap for paired processes on one host. Use `--realtime-priority 80` and check the worker's `SCHED_FIFO` verification for each lane. Direct polling puts NIC polling on those application threads.
4. For bandwidth, use at least 10 seconds for hardware measurements and verify traffic reached each intended queue. Keep stable one-second `mlnx_perf` samples. For internal hardware loopback, use `vport_loopback_bytes` once and verify flat PHY counters. For cabled tests, confirm sender TX and receiver RX PHY counters. Report application rates and drain counts separately.
5. Save the command, build version, exit status, JSON, optional probe CSV, and tuning output. Software latency includes TX and RX processing. Use `--hardware-rtt` on both raw ibverbs roles to time the echo from the initiator's request TX CQE to its reply RX hardware timestamp. Both timestamps come from the initiator's NIC. Report timeouts, zero-delivery queues, and cases where only CPU timing was available.

See [DAQIRI perftest](../../docs/benchmarks/perftest.md) for example commands.
